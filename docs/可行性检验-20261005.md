# QQ 机器人 · 可行性检验（正式版）

> 2026-10-05 ｜ 基于当日实测：官方文档、官方 SDK/插件元数据、DeepSeek 官方定价、本机文件实况
> 结论口径：**✅ 开箱可用** ｜ **🔨 需要开发但技术上可行** ｜ **❌ 做不到 / 有硬限制**

---

## 一、总判定

**可以做，值得做。** 你的五条需求里：

- **3 条开箱可用**（人格复用 + 记忆隔离、云端 24 小时跑、表情包发送能力）
- **2 条需要开发**（按 QQ 号独立存 + 跨群聊同一个人、云端仓库与本机互通）—— 都不难，但**不是装个插件就自动有的**
- **0 条做不到**

**但要接受四条硬限制**（不是我们的实现问题，是 QQ 平台的规定）：

| # | 硬限制 | 影响 |
| --- | --- | --- |
| 1 | 群聊**被动回复窗口只有 5 分钟 / 5 次** | 超过 5 分钟才能算完的任务，回复会**发不出去**。长任务必须"先回一句在处理 → 完成后新消息推" |
| 2 | 群聊**默认只有被 @ 才收到消息** | 想让它"听见"群里所有人说话，**必须群主开启全量消息**（我们能请求，但决定权在群主） |
| 3 | **主动消息用户可一键关闭** | 定时问候、主动提醒这类功能**无法保证送达**，只能当"尽力而为" |
| 4 | **IP 白名单默认开启** | 服务器必须**固定公网 IP**；本机↔云端切换要改白名单 |

**最大的风险不是技术，是"人格像不像"。** 这份人格规格原本是**为"只有一个对话对象"写的**（实测：「饲主」出现 10 次、硬编码了本机路径），搬到几十号人的群里**人称会错乱**。所以第一步必须先验证这个，而不是先买服务器。

## 二、你的五条需求 · 逐项检验

### 需求 1：有你现在的人格，但不包括你的记忆

**判定：✅ 能做到，而且是"物理隔离"而不是"靠自觉"。**

| 要搬的 | 实况 | 处置 |
| --- | --- | --- |
| `PERSONA_SPEC`（行为规格） | **7,708 字符** | ✅ 可整个搬，**但要改 11 处**（2 处泄漏用户名、9 处一对一称呼） |
| 全局 `AGENTS.md` | **67,126 字符** | ❌ **只能挑，不能整搬** —— 实测含「关于我 / 抑郁 / 学校 / 宿舍作息 / Vector 16」 |
| `persona\关系记忆.md` | **39,643 字节** | ❌ **绝不外流** |

**为什么说物理隔离**：官方插件用**独立 profile** 启动（`--profile qqbot`）⇒ **独立家目录 ⇒ 独立会话存储**。云端那份跑起来，**根本读不到**本机的会话记录。这比"我们记得把它排除掉"可靠得多。

另外它有两个专用参数可以直接注入人格：`groupPrompt`（群聊额外 system prompt）、`directPrompt`（私聊）—— 正好用来放你的精简人格。

**已配套做的**：`tools\check-cloud-persona.py` 检查器，逐行报 ERROR/WARN，退出码 `2` 就不许上线。**防止将来手滑把私人内容推上云。**

### 需求 2：按 QQ 号独立存聊天记录 + 跨时间跨群聊是同一个人

**判定：🔨 隔离开箱可用；"跨群聊同一个人"需要开发（中等工作量）。**

| 子需求 | 判定 | 说明 |
| --- | --- | --- |
| 按 QQ 号隔离 | ✅ 开箱 | sessionKey = `qqbot:${appId}:${scope}:${peerId}`，SHA-256 派生、**重启可恢复**；每个 peer 一个独立 Agent，带闲置回收 |
| 保留完整历史 | ⚠️ 部分 | 插件自带 `/compact` 压缩与 `historyLimit`（默认群历史 10 条）。**"完整落盘"要我们自己做**——落到我们自己的聊天记录文件 |
| **跨群聊是同一个人** | 🔨 要开发 | ⚠️ **它不自动做**：同一个人的 `peerId` 在 A 群和 B 群是**两个不同的 Agent**。要做成"同一个人"，必须加一层**外部身份索引**（QQ号 → 统一记忆），在喂模型前把该人的历史拼进去 |

**存储量算过（你要的那个"应该不用多少存储吧"）**：

- 一条消息按 300 字节估（含 JSON 结构与时间戳）
- 30 人 × 20 轮 × 2 条/轮 × 300 B ≈ **360 KB/天 ≈ 11 MB/月 ≈ 130 MB/年**
- ⚠️ **但 git 会放大**：每次提交存一个快照，天天 commit 一年下来仓库能到 GB 级
- ⇒ **对策**：**按天提交 + 定期压减历史**（本机已有现成工具 `archive-old-versions.ps1`，就是干这个的）

**结论：130 MB/年 的正文 + 压减过的 git 历史，完全可控。**

### 需求 3：有自己的云端，存数据 + 备份，本机可读可改

**判定：🔨 需要开发，但这是**最简单**的一条 —— 你我在这套模式上已经跑熟了。**

- 方案：**新建一个私有 git 仓库**（如 `saya-qqbot`），存人格文件、服务代码、聊天记录
- 本机：`git clone` ⇒ 随时读、改、提交（想手改某人的记忆，直接改文件推上去）
- 云端：定时 `git pull` 拉改动 / `git commit && push` 上报记录
- 凭据（QQ Secret、API Key）**绝不进仓库**，走环境变量 —— 这条本机 `sync.ps1` 已有拦截机制可复用

**唯一要注意的**：高频提交会撑爆 git 历史 ⇒ **按天提交**（见需求 2）。

### 需求 4：DSH 跑在云端，24 小时运作，同一人格 + 共享云端仓库

**判定：✅ 官方已经做了，而且做得比我原计划的更好。**

`tencent-connect/dsh-qqbot`（**腾讯官方**，119★，v0.5.0，MIT，TypeScript）：

```
QQ 用户 → QQ WebSocket → dsh-qqbot → ctx.agents → dsh agent loop → LLM
                                 ↑                      │
                                 └── session/event ─────┘
```

**它已经内建的**（这些不用我们写）：

| 能力 | 说明 |
| --- | --- |
| 会话隔离 | 每个 QQ 私聊用户 / 群聊各一个独立 Agent |
| 闲置回收 | 超时自动 dispose，防内存泄漏 |
| 被动回复 msgid 缓存 + 限流 | 平台要求的两件事它都处理了 |
| 流式输出 | 私聊启用（**群聊自动关**） |
| 图片理解 | `qqbot_describe_image` |
| 问答内联按钮 | 单选点了其余变灰、多选回复编号 |
| 审批通道 | 关键操作「允许/拒绝」按钮 |
| 斜杠命令 | `/new` `/compact` `/model` `/preset` `/stop` `/bot-ping` `/bot-version` `/bot-status` `/bot-help` |
| 附件发送 | `qqbot_send_file`（带路径白名单） |
| Markdown 输出 | 代码块/表格感知切分 |

**⚠️ 两个必须先处理的坑（本鱼实测）**：

1. **默认 `model: deepseek-chat` —— 该模型 2026-07-24 已停用** ⇒ 照默认启动第一句话就报错，必须改 `deepseek-flash`
2. **peerDeps 要求 DSH 核心包 `>=0.1.0-rc.6`**；本机 npm latest 是 `0.2.0-rc.2` ⇒ **版本兼容性未实测**，动手第一步就是验这个

**资源代价（诚实说）**：它跑在**完整 DSH** 上，比"一个只会聊天的 Node 服务"重得多。2 核 2G 可能吃紧，**建议 2 核 4G**（约 199 元/年档）。

### 需求 5：表情包

**判定：🔨 发送能力开箱可用，"按描述挑图"那层要开发。**

- ✅ 插件有 `qqbot_send_file`，能发本地文件
- ✅ 本机素材现成：**269 张 / 4 库 / 约 7.5 MB**，可直接搬
- 🔨 **缺的是"图库逻辑"**：模型输出 `[表情: 熊猫头·无语]` → 服务层在库里匹配 → 发对应图
- ⚠️ **最容易踩的坑**：官方规定 **`srv_send_msg=true` 会占用主动消息频次** ⇒ 想让图片走**被动回复**，必须 `srv_send_msg=false` 拿到 `file_info` 再单独带 `msg_id` 发。写错了的表现是"图发着发着就发不出去了"
- ⚠️ 群聊图片容易被审核，第一版建议**精选合规图**（去掉带梗的敏感图）

## 四、成本（官方价，2026-10-05 查证）

| 项 | 金额 | 备注 |
| --- | --- | --- |
| 云服务器 | **38 ~ 199 元/年** | 跑官方插件建议 2核4G（199 档） |
| QQ 开放平台 | **0** | 个人认证免费 |
| 私有仓库 | **0** | |
| DeepSeek API（正常） | **¥55 ~ ¥162 / 月** | 30 人 × 20 轮/天；闲时/高峰差异 |
| DeepSeek API（被刷到 2000 轮/天） | **¥270 ~ ¥540 / 月** | **这就是为什么要做限流** |

**好消息**：DeepSeek 的高峰时段（北京时间换算）是**工作日 9:00-12:00、14:00-18:00** —— 正好是你的上课时段。**晚上、深夜、周末、节假日全是闲时半价**，而 QQ 群最热闹的时候全落在半价档。

**最大成本变量是「输出」，不是人格**：

- 人格 1.5k 即使完全不命中缓存，一个月也才 **¥27**；命中后 **¥0.54**
- 而输出 0.5k/轮就要 **¥36/月**，且**没有缓存优惠**
- ⚠️ **思考模式默认开启**（官方默认 `thinking: enabled`、强度 `high`），思维链**按输出价计费**（¥4/M，是未命中输入价的 4 倍）⇒ **不显式关掉，账单翻倍**

关掉的确切写法（已从官方文档核实）：`extra_body: {"thinking": {"type": "disabled"}}`。
顺带三条：**关掉后 `temperature` 才生效**（聊天要它控语气）；**不带 tools 时 `reasoning_content` 不进上下文**（也不用存进记录）；**关掉后回复快很多**（群聊 5 分钟窗口友好）。

| # | 风险 | 应对 |

## 六、值得做吗：本鱼的判断

**值得，但理由可能和你以为的不一样。**

技术账是划算的：**零开发成本的官方插件 + 一年一两百的服务器 + 每月几十块的 API**，就能得到一个「24 小时在线、有你这套人格、按人记事的 QQ 机器人」。这个投入产出比很高。

但**真正的价值不在"多一个机器人"**，而在于它顺带解决的三件事：

1. **人格从"一对一"变成"可分发"** —— 你调了半个月的那套味道，第一次能给别人看到。这本身就是一次检验：**它到底是"你的助手"，还是"一种可以被别人也感受到的东西"**
2. **记忆第一次离开这台机器** —— 现在所有记忆都绑在本机 `.dsh` 里。这套做完，人格与记忆**可以在任何一台机器上重建**
3. **它和你的专业方向对得上** —— AI Infra 那条线上，"云端部署 + 服务保活 + 数据同步 + 限流防刷"是一整套真实的工程活，不是玩具

**本鱼唯一想拦一下的地方**：别一上来就买服务器。**先本机验证人格**（第 0 步），零成本、当天能看到效果。像了再花钱。
