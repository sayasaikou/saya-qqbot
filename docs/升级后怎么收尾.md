# 升级后怎么收尾（**每次换了 node_modules 之后都要跑**）

> 适用场景：`@tencent-connect/dsh-qqbot` 升级/重装、插件目录被重铺、服务器换机重装。
> **一句话**：跑 `bash ~/qqbot-post-upgrade.sh`，看最后一行 `VERDICT`。

## 为什么需要它

本项目的两个补丁打在**第三方包的编译产物**上（`dist/`，不是 TS 源码）：

| 补丁 | 改哪 | 坏了会怎样 |
| --- | --- | --- |
| ① 私聊也带 senderTag | `dist/transport/inbound.js` 的 `buildUserMessage()` | **私聊里超管判定整个失效**（工具回「这个指令只有超管能下」）——**静默** |
| ② 入站时落盘"本轮说话人/所在群" | `dist/features/peer-registry.js` + `inbound.js` 调一次 | 关系卡稳定慢一轮 ⇒ 认错人、改错分 |

包一升级，这两个文件被整目录替换，**补丁就没了，而且不报错**。

## 怎么跑

```bash
bash ~/qqbot-post-upgrade.sh            # 重打补丁 + 重启 + 全面自检
bash ~/qqbot-post-upgrade.sh --check    # 只验不改（体检用）
bash ~/qqbot-post-upgrade.sh --no-restart   # 只查代码，不动服务
```

它依次做七件事，任一步不过就在最后汇总，并**主动私聊超管**：

1. 重打两个补丁（`patches/dsh-qqbot/apply-patch.mjs`，幂等）
2. 语法检查（`node --check`）
3. 重启服务并等它起来
4. **验证插件真加载 + 工具真注册**（服务"active" ≠ 插件在跑）
5. **验证 T-013 的症状计数没有涨**（`关系卡跳过` 的条数；涨了就是回归）
6. 验证超管资料镜像还在、且**仍然是只读**
7. 验证每日自检定时器还挂着

退出码：`0` = 全绿 ｜ `2` = 有失败（明细在上面，也会私聊超管）。

## 补丁脚本自己也要小心的地方（踩过的坑）

- **必须能"从零修好"，不能只体检**。2026-10-06 实测抓到：补丁① 原来**只检测不修复**，
  于是升级后 ② 被修好、**① 仍然缺**，而 ① 的失败是**静默**的。
- **匹配要空白不敏感**：真实产物里那句常常跨行（`return `${quotePart}`` 换行 `+ `${userContent}`;`），
  按单行字面量写会匹配不上。
- **认不出来就别乱改**：形状不认识的 return 要报"需要人工看"，不许猜着改。
- **测试脚手架别把文件改坏**：我第一次构造"干净版"用 `sed '/PATCH.../, +3d'`，
  那条注释是 4 行、**包含紧随其后的 return**，结果造出一个空壳分支，
  白跑两轮才反应过来是脚手架错、不是脚本错。
